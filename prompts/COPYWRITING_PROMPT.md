# COPYWRITING PROMPT — voice & language

All user-facing copy on this site is **English**. Voice: a builder talking to
another builder — confident, concrete, lightly cinematic, never salesy.

## Rules

1. **Concrete beats abstract.** "An irrigation network keeping 2,000 palm trees
   alive" — not "innovative IoT solutions".
2. **Verbs over adjectives.** Ship, build, run, replace, lock, verify.
   Banned words: passionate, innovative, cutting-edge, seamless, solutions,
   leverage, empower, journey (as metaphor), "digital transformation".
3. **Evidence or silence.** Every claim must be checkable (live URL, repo,
   examined thesis, hardware in a field). No invented numbers — ever.
4. **Short sentences carry the weight.** One idea per sentence. Fragments are
   fine for rhythm. Read it aloud; if you stumble, rewrite.
5. **The narrative arc is fixed** (master prompt): arrival → who → how I think →
   proof (work) → breadth (live sites) → capability map → history → invitation.
   New copy must know which beat it serves.
6. **Microcopy is set dressing** — kickers (`.mono`) are terse and cinematic:
   "Final scene", "Live on the internet", "The road here". Keep that register.
7. **Titles ≤ 4 words. Taglines ≤ 20 words. Ledes ≤ 35 words.**

## Self-review

Delete every sentence that could appear on any other developer's portfolio
unchanged. What survives is the copy.
